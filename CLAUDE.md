# Правила работы над проектом

## Контекст

Пользователь — начинающая, проходит обучение Claude Code. Нужны последовательные действия и простые объяснения. Работа занимает 1,5–2 часа в день. Готовность — 19 ноября 2026 года, сдача — 20 ноября.

Цель — помочь пользователю создать и понять работающий MVP, оформить GitHub-репозиторий и подготовить основу будущей фриланс-услуги.

## С чего начинать

1. Прочитай PROJECT.md — согласованное описание и границы первой версии.
2. Прочитай PLAN.md — задачи и фактическое состояние.
3. Используй IDEAS.md для предложений, выходящих за границы MVP.
4. Проверь, какие файлы и инструменты уже существуют. Не считай задачу выполненной по одному наличию файла.
5. Назови ближайшую незавершённую задачу и ожидаемый результат. Если пользователь попросила только планирование, закончи на плане. Если попросила реализацию, приступай к согласованной задаче без дополнительных формальных подтверждений.

## Общение и темп

- Отвечай на русском языке, коротко и понятно.
- Объясняй новые термины при первом использовании.
- Выполняй работу небольшими проверяемыми этапами.
- Показывай точные команды, адрес страницы и ожидаемый результат, когда пользователю нужно что-то сделать самой.
- Различай команды для PowerShell и сообщения, которые нужно написать Claude Code.
- Не предлагай несколько равнозначных технических вариантов без необходимости: выбирай простой подходящий и объясняй выбор.
- После этапа сообщай: что изменено, что проверено, что пользователь может проверить сама и какой следующий шаг.
- Не запрашивай повторное разрешение на обычные действия внутри согласованной задачи. Соблюдай действующие ограничения среды и запросы разрешений инструментов.

## Границы реализации

- HTML, CSS и JavaScript без сборки и сторонних библиотек.
- Интерфейс и материалы на русском языке.
- Одна анкета, проверка полей, учебный пример, просмотр и скачивание брифа.
- Анализ брифа выполняется отдельным шагом через скилл Claude Code.
- Не добавляй API, базу данных, авторизацию, интеграции и отправку сообщений в первую версию.
- Не создавай сайт через внешние конструкторы и не разворачивай приложение в облаке: задание требует локального запуска и репозитория.
- Для запуска сначала проверь уже установленные инструменты и выбери простой воспроизводимый способ. Не добавляй зависимости, если задача решается доступными средствами.
- Новые функции записывай в IDEAS.md; не расширяй MVP без решения пользователя.
- Не перезаписывай пользовательские изменения без необходимости. Сначала прочитай существующие файлы.

## Работа с данными и качеством

- Для демонстрации используй только явно вымышленные данные из PROJECT.md.
- Не отправляй содержимое анкеты во внешние сервисы из приложения.
- Выводи введённые пользователем значения как текст, не как исполняемый HTML.
- Сохраняй русский текст и переносы строк; экспортируй бриф в UTF-8.
- Не выдумывай факты, показатели, экономию времени и результаты проверок.
- Разделяй сведения из описания, гипотезы, вопросы и рекомендации.
- Сообщения клиентам остаются черновиками для проверки пользователем.

## Проверки

- Проверяй основной сценарий и существенные ошибки: пустые обязательные поля, пробелы, неполное заполнение, обновление результата, скачивание и русский текст.
- Для скилла проверь полное, неполное и противоречивое описание.
- Записывай выполненные проверки и их реальные результаты в CHECKS.md, когда начнётся разработка.
- Не подключай сложную систему тестов ради простой формы. Используй подходящие по масштабу проверки.
- Если браузерная проверка недоступна, явно сообщи это и дай пользователю короткую ручную проверку. Не утверждай, что приложение визуально проверено, если это не так.
- Скриншоты должны показывать реально работающее приложение.

## Скилл проекта

- Создай его на соответствующем этапе плана в .claude/skills/process-review/SKILL.md.
- Перед созданием проверь актуальные требования к формату скиллов Claude Code.
- Скилл должен работать с брифом этого проекта и выдавать структуру из PROJECT.md.
- Не устанавливай сторонние наборы навыков только ради выполнения задания. Если используются чужие материалы, укажи источник и соблюдай лицензию.

## Документация и сдача

- Обновляй PLAN.md по фактически выполненной и проверенной работе.
- В конце занятия обновляй «Текущее состояние» и добавляй запись в журнал, чтобы работу можно было продолжить в новом сеансе.
- В README.md укажи задачу, функции, проверенные команды запуска, использование скилла, учебный пример, реальные скриншоты и ограничения.
- Не описывай будущие функции как уже работающие.
- Публикация на GitHub — финальный этап плана. Используй GitHub CLI, как требует задание; сначала проверь учётную запись, состав файлов и доступность репозитория преподавателю.
- Не публикуй ключи, пароли, личные материалы и реальные клиентские данные. Не исключай скилл проекта из репозитория.
- Не отмечай сдачу выполненной, пока пользователь действительно не отправила ссылку преподавателю.
