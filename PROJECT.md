# Помощник консультанта: подготовка к разбору бизнес-процесса

Статус на 16 ноября 2026 года: MVP, скилл, примеры и скриншоты опубликованы на GitHub. Репозиторий: https://github.com/n13089436-cyber/consulting-assistant. Отправка ссылки преподавателю пока не подтверждена.
Срок готовности: 19 ноября 2026 года. Сдача: 20 ноября 2026 года.
Доступное время: 1,5–2 часа в день.

## 1. Идея проекта

Я создаю небольшое локальное приложение, которое помогает собирать информацию о рабочем процессе клиента и готовить её для анализа в Claude Code.

Проект состоит из приложения с анкетой и отдельного скилла — инструкции для Claude по разбору собранных данных.

## 2. Какую рабочую задачу я хочу автоматизировать

Я планирую оказывать фриланс-услуги по разбору и улучшению отдельных бизнес-процессов.

Перед консультацией нужно собрать исходные данные, привести описание клиента к понятной структуре, определить недостающую информацию и подготовить вопросы. Если каждый раз делать это с нуля, можно пропустить важные детали или потратить много времени на оформление.

Я хочу автоматизировать сбор, проверку и оформление исходного описания, а затем использовать Claude для подготовки предварительного разбора.

## 3. Для кого предназначен проект

Основной пользователь — я как начинающий консультант.

В первой версии я самостоятельно заполняю анкету на основании обращения клиента или заметок. Клиенту не требуется устанавливать приложение или пользоваться Claude.

Для демонстрации используется вымышленная ситуация небольшой компании.

## 4. Цель проекта

Создать повторяемый рабочий сценарий:

**Описание процесса → заполненная анкета → структурированный бриф → предварительный разбор в Claude Code → моя проверка → материал для консультации.**

Бриф — это краткое описание задачи и исходных данных, собранное по единому шаблону.

## 5. Что делает приложение

В приложении можно указать:

- название и цель процесса;
- событие, с которого начинается процесс;
- основные действия и их последовательность;
- участников и ответственных;
- используемые инструменты;
- известные проблемы;
- желаемый результат.

Приложение проверяет обязательные поля и формирует бриф. Для необязательных незаполненных пунктов оно указывает, какие сведения нужно уточнить.

Пользователь может просмотреть бриф и скачать его как текстовый Markdown-файл, который удобно читать человеку и Claude.

Для демонстрации предусмотрена кнопка заполнения учебного примера.

### Уточнение для реализации формы

Обязательные поля: название процесса, цель процесса, последовательность действий и желаемый результат. Значения, состоящие только из пробелов, считаются пустыми.

Остальные поля необязательные. При их отсутствии бриф содержит пометку «Не указано — нужно уточнить». Приложение не дополняет описание выдуманными данными.

Форма и результат должны сохранять русский текст и переносы строк. Данные не отправляются во внешние сервисы. В первой версии нет автоматического сохранения между сеансами: пользователь скачивает бриф перед закрытием страницы.

## 6. Что делает скилл проекта

Скилл помогает Claude разбирать подготовленный бриф по одной последовательности:

1. Описать текущее устройство процесса.
2. Выделить проблемы, которые следуют из исходных данных.
3. Отдельно перечислить гипотезы о возможных причинах.
4. Подготовить уточняющие вопросы.
5. Предложить до трёх приоритетных действий.
6. Составить план первичной консультации.
7. Подготовить черновик ответа клиенту.

Скилл запрещает выдавать предположения за факты и придумывать показатели, сроки или финансовые результаты. Если данных недостаточно, Claude должен обозначить пробелы и предложить способ их уточнения. Если исходные сведения противоречат друг другу, противоречие нужно явно отметить.

Скилл размещён в `.claude/skills/process-review/SKILL.md`. Примеры входных брифов и разборов сохранены в папке `examples`.

## 7. Учебный пример

Небольшая студия получает заявки через электронную почту и мессенджеры.

Сотрудники вручную переносят обращения в таблицу. Единого ответственного за обработку заявок нет. По описанию руководителя, некоторые обращения остаются без ответа. Точная частота таких случаев и время ответа пока не измеряются.

Задача — подготовиться к консультации: описать процесс, определить недостающие сведения и предложить первые шаги для его изучения и улучшения.

Все данные примера вымышленные. Утверждения руководителя нужно обозначать как сведения из учебного описания, а не как независимо проверенные факты.

## 8. Техническая реализация

Первая версия — локальное приложение с интерфейсом на русском языке, созданное с помощью Claude Code.

Основа: HTML, CSS и JavaScript без сборки, сторонних библиотек и базы данных. Способ локального запуска выбирается с учётом уже установленных на компьютере инструментов.

Код и документация хранятся в GitHub-репозитории. Публикация выполняется через GitHub CLI. Скилл размещается в том же репозитории.

## 9. Границы MVP — первой рабочей версии

В MVP входят:

- одна анкета;
- проверка обязательных полей;
- загрузка учебного примера в форму;
- формирование и скачивание брифа;
- один скилл для разбора процесса;
- пример результата работы скилла;
- инструкция запуска и скриншоты.

Анализ выполняется отдельным шагом в Claude Code. Приложение не обращается к ИИ самостоятельно.

Подключение ИИ внутри приложения, база клиентов, авторизация, интеграции и отправка сообщений относятся к последующим версиям.

## 10. Критерии готовности

Проект готов к сдаче, если:

- приложение запускается локально;
- учебный пример проходит весь сценарий;
- при отсутствии обязательных данных появляются понятные сообщения;
- скачанный бриф соответствует заполненной форме и корректно отображает русский текст;
- скилл создаёт разбор с разделением фактов, гипотез и вопросов;
- работа проверена на полном, неполном и противоречивом описании процесса;
- код, скилл, README, скриншоты и демонстрационные материалы опубликованы в одном репозитории;
- преподаватель может открыть репозиторий и воспользоваться инструкцией запуска.

## 12. Практическая польза и развитие

После обучения я смогу использовать проект для подготовки к первичным консультациям.

Чтобы оценить пользу, я сравню время подготовки одного и того же примера вручную и с помощником, а также проверю полноту полученного материала. Пока измерения не выполнены, экономия времени не считается доказанной.

Дальнейшее развитие будет идти небольшими шагами: один новый навык или одна функция за раз. Идеи будут храниться отдельно от текущих задач в IDEAS.md. После каждого изменения я буду повторно проверять проект на сохранённых примерах.

Итоговые рекомендации и сообщения клиенту всегда проходят мою проверку.
